# 교회 회계 프로그램 기획서 (초안 v0.1)

> 이 문서는 목사님과의 대화 내용을 정리한 초안입니다.
> **[확정]** 은 목사님이 직접 말씀하신 내용, **[제안]** 은 제 의견(검증되지 않음), **[확인 필요]** 는 아직 모르는 내용입니다.

## 1. 목적

한인교회의 헌금(수입)과 지출을 기록·관리하고, 부서별 예산 대비 집행 현황과 공동의회·제직회용 결산 보고서를 회계사 없이도 만들 수 있게 한다. 핵심은 **핸드폰으로 영수증(및 헌금 관련 서류) 사진을 찍으면 내용이 자동으로 채워지는 것**이다.

## 2. 확정된 요구사항

| 항목 | 내용 | 상태 |
|---|---|---|
| 장부 | 합병된 두 교회의 장부를 **하나로 합침**. 과거 기록이 불확실하므로 **현재 보유 자금을 시작 잔액**으로 입력하고 거기서 새로 시작 | [확정] |
| 사용자 | 3명. 수정·기록은 지정된 2명, 담임목사는 열람 | [확정] |
| 헌금 종류 | 주일헌금, 십일조, 선교헌금, 건축헌금, 작정헌금, 감사헌금. **종류는 추가 가능** | [확정] |
| 헌금 방식 | **현금**과 **온라인 입금**을 구분하여 기록 | [확정] |
| 지출 | 영수증 사진 → OCR → 매장·날짜·품목·품목별 금액·총액 자동 입력 (Coles, Woolworths 등 호주 영수증) | [확정] |
| 예산 | 제직회에서 **부서별 예산**을 정하고, 예산 대비 집행액을 계산 | [확정] |
| 개인별 내역 | 성도별 연간 헌금 합계 조회, 헌금 내역서(영수증) 발행 | [확정] |
| 보고서 | 공동의회 보고용 결산. 회계사 없이 직접 보고할 수 있는 수준을 목표로 함 | [확정] |
| 언어 | 한국어 화면. 영어 병행 가능한 구조 (회계사 소통용) | [확정] |
| 인프라 | 이미 쓰는 Cloudflare 계정·도메인 사용. 유료 플랜 사용 가능 | [확정] |
| 손글씨 OCR | 금액 위주로 정확도를 시험해 보고 판단 | [확정] |

## 3. 사용자와 권한

- **기록 담당 2명**: 헌금 입력, 지출 입력, 영수증 사진 업로드, 수정
- **열람 1명(담임목사)**: 모든 화면 조회만 가능
- 모든 입력·수정·삭제에 **변경 기록(누가, 언제, 무엇을)** 을 남긴다. 삭제는 실제 삭제가 아니라 "취소 처리"로 한다. [제안]
- 로그인: Cloudflare Access(이메일 일회용 코드) 방식을 검토한다. [제안 / Phase 1에서 현재 문서로 확인 필요]

## 4. 데이터 구조 (초안)

- `users`: 이름, 이메일, 역할(기록/열람)
- `members`: 성도 명부 (이름, 연락처 선택). 헌금자 기록용
- `fund_types`: 헌금 종류 (위 6개로 시작, 추가 가능)
- `offerings`: 헌금 기록
  - 날짜, 헌금 종류, 금액, 방식(현금/온라인), 성도(비워 둘 수 있음), 메모, 원본 사진(있으면)
  - 주일헌금처럼 헌금자를 특정하지 않는 경우를 위해 성도는 선택 항목 [제안]
- `departments`: 부서
- `expense_categories`: 지출 항목 (식사·애찬, 교육 물품, 간식 등)
- `budgets`: 회계연도 × 부서 × 금액 (지출 항목별 예산은 선택) [제안]
- `expenses`: 지출 기록
  - 날짜, 매장, 부서, 지출 항목, 총액, GST, 지출한 사람, 결제 방식, 영수증 사진, 상태(임시/확정/취소)
- `expense_items`: 영수증의 품목별 내역 (품목명, 수량, 금액)
- `opening_balances`: 시작 시점 잔액 (현금 보관분 / 은행 계좌 등으로 나누어 입력)
- `audit_log`: 변경 기록

## 5. 기술 구성 [제안]

- Cloudflare **Workers**(서버), **D1**(데이터베이스), **R2**(사진 보관)
- 핸드폰 브라우저에서 바로 쓰는 웹앱(카메라로 촬영·업로드). 앱스토어 설치는 필요 없음
- 현재 홈페이지와 분리된 하위 주소(예: `finance.교회도메인`) 사용
- 백업: D1 복원 기능(Workers 유료 30일) + 월 1회 전체 내보내기를 R2에 자동 보관
- 비용: Workers 유료 월 최소 $5 수준 (Cloudflare 문서 기준, 결제 전 공식 가격 페이지 재확인 필요)
- OCR는 **교체 가능한 구조**로 만들고, 샘플 영수증으로 여러 방식을 비교한 뒤 선택한다. 정확도는 아직 모른다.
- OCR 결과는 **항상 사람이 확인·수정한 뒤 저장**한다.

## 6. 개발 단계

1. **기초**: 로그인·권한, DB 구조, 헌금 종류·부서·지출 항목 설정, 시작 잔액 입력
2. **헌금 입력**: 직접 입력(현금/온라인 구분), 성도 명부
3. **지출·예산**: 부서별 예산 입력, 지출 직접 입력, 예산 대비 집행 현황
4. **영수증 OCR**: 사진 촬영 → 자동 입력 → 확인 → 저장
5. **보고서**: 월별 수입·지출, 공동의회 결산, 엑셀·PDF 내보내기
6. **개인별 헌금 내역서**, 손글씨 헌금 서류 OCR 실험, 은행 거래내역(CSV) 대조

## 7. 확인이 필요한 사항

1. **회계연도 기준**: 1~12월인가, 호주 회계연도(7~6월)인가? 예산과 결산 보고 기간이 이에 따라 정해진다. [확인 필요]
2. **부서 목록과 지출 항목**: 실제 부서 이름 [확인 필요]. 아래는 제가 임시로 적은 예시이며 실제 이 교회의 부서가 아니다.
   - 예시: 예배부, 교육부(유아·아동·청소년), 친교부(식사·애찬), 선교부, 관리부(건물·시설)
3. **홈페이지 주소**: 현재 Cloudflare에서 어떤 방식으로 운영 중인지 확인 필요
4. **샘플 사진**: 영수증 몇 장, 헌금 서류 몇 장 (이름은 가려서). 실제 재정 자료는 이 저장소에 올리지 않는다.
5. **기부금 영수증**: 세금공제용 영수증은 ATO의 DGR 자격이 있어야 한다고 알고 있으나 이 교회의 해당 여부는 모름 [확인 필요]. 우선 "연간 헌금 내역서"부터 만든다.
6. **ACNC 재무 보고 형식**: 교회 규모에 따라 요구 사항이 다를 수 있음 [확인 필요]
7. **GST 처리**: 영수증의 GST 금액을 기록할지, 교회가 GST 등록 사업자인지 [확인 필요]
8. **OCR 외부 전송**: 영수증 이미지를 외부 AI 서비스로 보내는 것을 허용하는지 [확인 필요]
9. **개인정보**: 헌금자 이름·금액은 민감한 정보. 호주 개인정보 관련 규정이 이 교회에 적용되는지 [확인 필요]

## 8. 하지 않는 것 (현재 범위 밖)

- 급여·세금 신고, 복식부기 전체 기능, 온라인 결제(카드 헌금) 연동
- 과거 장부 복원 (기록이 불확실하므로 시작 잔액부터 새로 시작)
